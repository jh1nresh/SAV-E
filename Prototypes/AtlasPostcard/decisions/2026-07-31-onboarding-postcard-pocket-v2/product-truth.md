# Product Truth

## User Job

Understand in one first-run proof that SAV-E can accept a messy place clue, find a likely place, and save it only after the user confirms it.

## Audience and Usage Context

Consumer travel and food savers, often arriving from a shared social or map link on a phone. The first run must be understandable in seconds.

## Stakes and Trust Requirements

SAV-E must not imply that an uncertain candidate is already true or saved. The source must remain visible and confirmation must be explicit.

## Desired and Prohibited Feelings

- Desired: guided, collectible, calm, unmistakably SAV-E.
- Prohibited: generic form onboarding, analytics dashboard, childish decoration, or a fake navigation product.

## Critical Flow

Language -> enter or use a Source Clue -> inspect Review Candidate -> explicitly confirm -> see private Map Stamp -> open SAV-E.

## State Model

- Source Clue: coral, unresolved, editable, source visible.
- Review Candidate: sky, probable, evidence retained, user decision required.
- Map Stamp: mint/forest, confirmed by the user, private, source retained.

## Fixed Navigation

No root tabs during first run. Back, 4-step progress rail, and one bottom action remain fixed.

## Required Screens

Clue, Review, Map Stamp at 402 x 874 pt. Language remains unchanged.

## Existing Brand Assets

Memo mascot, Saves envelope, Paper Texture, Koffee Mameya thumbnail, SAV-E lockup, Atlas palette/type/shapes.

## Platform and Viewport

Native SwiftUI, iPhone portrait, reference viewport 402 x 874 pt, Light Mode.

## Implementation Constraints

Preserve onboarding completion and clue-capture behavior; no network; no whole-screen raster; Reduced Motion shows final state directly.

## Facts Mockups Must Not Invent

No exact-place guarantee, automatic Map Stamp, public review, booking, navigation, account creation, or data sync claim.
